### 作ったきっかけ

福井県越前市のサンドーム福井では、1万人規模のライブが年に何度も開かれています。
ただ「今日サンドームに〇〇さん来るらしいよ」と直前に人から聞いて知ることが多く、
知っていれば行きたかった公演を何度も逃していました。

好きなアーティストなら SNS をフォローしているので気づけますが、出演する全アーティストを追うのは難しいものです。会場の公式カレンダーに載る前から先行受付が始まる場合もあり、「いつ誰が来るか」と「いつ申し込めるか」を一度に確認できる場所がありませんでした。

そこで、公演予定とチケットの受付期間をまとめて確認できるサイトを作りました。

### 仕組み

情報収集には Claude Code のヘッドレスモード（`claude -p`）を使い、GitHub Actions の cron から毎晩実行しています。調査手順はプログラムではなく、WebSearch と WebFetch の使い方を日本語で書いた Markdown ファイルです。

収集結果は JSON で受け取り、Node.js のスクリプトで検証してから取り込み API へ送ります。サイトは Cloudflare Workers + Hono で SSR し、データは D1（SQLite）に保存しています。

公演ごとの詳細ページには、チケットの締め切りまでの残り時間を表示しています。schema.org の MusicEvent に沿った構造化データも出力しています。更新情報は RSS で配信しており、Slack の `/feed subscribe` から購読できます。

新しい公演やチケット受付を見つけると、こんな形で Slack に流れてきます。

### 収集で工夫したこと

#### 会場とアーティストの両方から探す

会場の公式カレンダーを確認するだけでなく、「"サンドーム福井" ツアー 2027」のように検索し、まだ公式カレンダーに載っていない公演も探します。この方法で、Vaundy の 2027 年 12 月公演を、先行受付中の段階で見つけることができました。

#### 調査を2段階に分ける

一晩ですべての公演を詳しく調べるのは難しいため、最初に全公演を広く確認し、その後、受付期間が分からなかった公演だけをアーティスト単位で調べます。2段階目では `GET /api/missing` を呼び出し、DB に足りない情報から調査対象を決めています。

#### LLMの出力の揺れを受け止める

同じプロンプト・同じ情報源でも、LLM の出力は毎晩少しずつ変わります。
アーティスト名の表記がぶれて同じ公演が 2 件に増えたり、
昨日取れていた受付期間が今日は `null` になって上書きで消えたりしました。

そこで、公演 ID は日付から決定的に生成し、受付は正規化した名前のハッシュで同一判定するようにしました。取り込む際も、値は情報が充実する方向にだけ更新します。`null` は「期間がなくなった」ではなく、「今夜の調査では分からなかった」と扱います。

#### 通知を必要なものに絞る

表記が変わっただけで通知しないよう、差分検知の対象から名前と URL を外しました。過去の公演、締め切り済みの受付、期間がまったく分からない受付も通知の対象外です。その結果、毎晩 30〜95 件流れていた RSS が、2 件程度に落ち着きました。
